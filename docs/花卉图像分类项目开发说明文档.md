## 1. 项目概述

### 1.1 项目目标

一条完整的图像分类工程流水线，以"花卉识别"为载体：

```
数据采集 → 数据清洗与划分 → CNN 训练 → Tkinter 界面推理
                 └────────→ 知识蒸馏（教师→学生） → 集成预测
                                        └→ 迁移学习（ResNet18，可选提升）
```

### 1.2 任务定义

- **类别（5 类）**：兰花、向日葵、玫瑰、菊花、郁金香
- **输入**：任意 RGB 图片，统一缩放到 128×128
- **输出**：类别名称 + 置信度（Softmax 概率），界面同时给 Top-3
- **数据**：自行采集，5 类 × 150 张 = 750 张；按 8:2 划分为训练 600 张、测试 150 张

### 1.3 技术栈与实测环境

| 类别 | 技术 | 作用 |
|---|---|---|
| 深度学习 | PyTorch 2.15.0+cpu | 模型定义、训练、推理 |
| 视觉工具 | torchvision 0.29.2+cpu | 数据增强、ResNet18 预训练权重 |
| 图像处理 | Pillow 13.0.0、OpenCV 5.1.0 | 读图、缩放、摄像头取帧、BGR→RGB |
| 图形界面 | Tkinter（Python 内置） | 登录窗口、主界面、摄像头界面 |
| 网页端 | Flask 3.1.3 + Jinja2 + SQLite | B/S 架构：登录、上传/摄像头识别、识别历史、管理端统计 |
| 数据采集 | requests 2.34.2 | 百度图片 JSON 接口 |
| 可视化 | matplotlib 3.11.2 | 训练曲线、混淆矩阵、预测图 |
| 进度显示 | tqdm | 训练进度条 |

```
Python 3.13.18 | 设备 CPU（CUDA 不可用）
```

代码用 `torch.device("cuda" if torch.cuda.is_available() else "cpu")` 自动选设备，有 GPU 不用改代码。

### 2.3 与原水果文档的三处刻意改动

1. **模型结构只留一份** `model.py`，不再在 5 个脚本里各复制一份。原文档那样做是为了"单文件独立运行"，代价是改结构要同步改五处，否则 `size mismatch`。`1.xxx.py` 只是文件名带数字，不影响 import 独立的 `model.py`。
2. **蒸馏公式修正为标准写法**：`α·T²·KL + (1-α)·CE`，α=0.7、T=4。原文档代码是 `α·soft + 1.0·hard` 且 α=2.0，软损失权重远超硬损失，不是标准写法。
3. **新增 `8.train_resnet.py`**：自建 CNN 在本数据集上只有 72.67%，换 ImageNet 预训练 ResNet18 后到 90.67%。界面会自动优先加载更强的模型。

## 5. 各模块实现详解

### 5.1 数据采集：`1.download_data.py`

#### 5.1.1 接口与必带参数

直接调用百度图片的异步 JSON 接口，不解析网页 HTML：

```
https://image.baidu.com/search/acjson?tn=resultjson_com&word=玫瑰&pn=0&rn=30&ala=0&nojc=0&newReq=1
```

`tn=resultjson_com` 要求返回 JSON；`pn` 是偏移量（0、30、60…）不是页码；`ala=0&nojc=0&newReq=1` 是实测必需的校验标记，缺了直接返回 `antiFlag`。

#### 5.1.2 这次实际踩到的坑：必须先拿 Cookie

不带 Cookie 直接请求接口，**返回 200 但只有 47 字节**：

```json
{"antiFlag":1,"message":"Forbid spider access"}
```

表现就是"接口通的、一张都下不到"。解决办法是先访问一次搜索结果页：

```python
self.session.get("https://image.baidu.com/search/index",
                 params={"tn": "baiduimage", "word": keyword}, timeout=20)
```

拿到 Cookie 后再打 acjson，同一关键词能返回 90~170 KB 的 JSON。代码里 `warm_up()` 在每个关键词开头调用，并在响应过短时自动重试一次。

#### 5.1.3 响应结构与字段

新版返回体 `data` 是**字典**，图片列表在 `data["images"]`，字段是小写 `thumburl` / `objurl`；旧版 `data` 是数组、字段是大写 `hoverURL` / `objURL` 且 objURL 是加密串。

因此代码做了两层解析：

```python
# 优先按 JSON 解析
items = data.get("images") if isinstance(data, dict) else data
url = item.get("thumburl") or item.get("middleURL") or item.get("objurl") or item.get("hoverURL")

# JSON 解析失败时正则兜底；两种情况都要还原 \u0026、\/ 转义
url = json.loads('"%s"' % raw)      # 或 raw.replace("\\/", "/").replace("\\u0026", "&")
```

> 第三个坑：URL 里的 `&` 被 JSON 转义成 `\u0026`，直接拿去请求会 400/404。必须还原。
>
> 第四个坑：`for item in data.get('data', [])` 在 `data` 变成字典后会遍历 20 个 key（字符串），`item.get(...)` 抛 `AttributeError` 并被外层 `except` 吞掉，表现同样是"不报错但 0 张"。排查时先 `print(type(data), data)`。

**取值建议：优先 `thumburl`。** 它是 `img*.baidu.com` 的缩略图（约 500 px），无防盗链；`objurl` 是原图，很多站点有防盗链。

#### 5.1.4 下载与清洗

```python
resp = session.get(url, stream=True, timeout=10)
if resp.status_code != 200: return False
if "image" not in resp.headers.get("Content-Type", "").lower(): return False   # 过滤 HTML 错误页
data = buf.getvalue()
if len(data) < 6 * 1024: return False                                          # 占位图
with Image.open(io.BytesIO(data)) as im:
    im.load()                                                                  # 真解码
    if min(im.size) < 100: return False                                        # 太小的缩略图
    im = im.convert("RGB")
```

最后统一 `im.save(path, "JPEG", quality=88)`。这样落盘的全是**可解码、RGB、尺寸合格的 JPEG**，后面的数据集清洗压力小很多。

去重：URL 集合 + 内容 hash 双重去重；编号接着已有文件往后排（`_next_index()`），重复运行不覆盖旧图。

#### 5.1.5 `single_data_download.py`

只采一个类别、页数更多，用 `importlib` 按文件路径加载 `1.download_data.py`（文件名带数字不能直接 import）：


### 5.3 训练：`3.train_cnn.py`

#### 5.3.1 数据清洗 `SafeImageFolder`

爬来的图必然有坏文件、灰度图、非图片，分两步处理：

```python
with Image.open(path) as im: im.verify()    # 查文件头
with Image.open(path) as im: im.load()      # 真解码，截断文件在这里暴露
```

校验不过的直接不计入样本（打印丢弃数量）。`__getitem__` 里用 `convert("RGB")` 统一 3 通道，并 `try/except` 兜底返回黑图，避免训练中途崩。

> 注意这里只校验、不在内存里缓存像素，几万张也不会 OOM。

#### 5.3.2 训练 / 评估预处理

| 训练集 | 测试集 |
|---|---|
| Resize(144,144) | Resize(128,128) |
| RandomRotation(20) | — |
| RandomHorizontalFlip(0.5) | — |
| RandomResizedCrop(128, scale=(0.75,1.0)) | — |
| ColorJitter(0.2/0.2/0.2) | — |
| ToTensor + Normalize(ImageNet 均值方差) | 同左 |

- 增强只在训练集做，测试集必须确定性，否则准确率抖动、不可复现；
- 归一化参数训练/测试/推理三处完全一致（`MEAN=[0.485,0.456,0.406]`，`STD=[0.229,0.224,0.225]`），这是新手最常犯的错。

#### 5.3.3 网络结构 `PlantCNN`

```
输入 [3,128,128]
Conv(3→32)+ReLU+Pool  → [32,64,64]
Conv(32→64)+ReLU+Pool → [64,32,32]
Conv(64→128)+ReLU+Pool→ [128,16,16]
Conv(128→128)+ReLU+Pool→[128,8,8]
Flatten 8192 → Dropout(0.5) → Linear(256) → ReLU → Dropout(0.5) → Linear(5)
```

- `padding=1 + kernel=3`：卷积不改变尺寸，只有池化减半；
- 4 次池化把面积缩小 256 倍；
- `128*8*8=8192` 是硬编码，改输入尺寸必须同步改（`model.py` 里加了断言防呆）；
- 参数量 2.34 M。

#### 5.3.4 训练循环三件套

```python
outputs = model(images)
loss = criterion(outputs, labels)
optimizer.zero_grad()     # 1. 清梯度，必须在 backward 之前
loss.backward()           # 2. 反向传播
optimizer.step()          # 3. 更新参数
```

- `model.train()` / `model.eval()` 必须切换，影响 Dropout 行为；
- 验证阶段 `torch.no_grad()`，否则内存持续增长；
- 损失按 `loss.item() * batch_size` 累加再除以总样本数，才是真实平均损失；
- 调度器 `StepLR(step_size=8, gamma=0.5)`。

#### 5.3.5 checkpoint

```python
torch.save({
    "arch": "cnn",                       # ★ 推理时靠它决定用哪个结构
    "model_state_dict": model.state_dict(),
```

### 5.5 摄像头界面：`5.classifier_camera_ui.py`

#### 5.5.1 打开摄像头：DSHOW 优先 + 预热

```python
for backend in (cv2.CAP_DSHOW, cv2.CAP_MSMF):
    cap = cv2.VideoCapture(index, backend)
```

#### 5.5.2 线程模型（重点）

**错误写法**（Windows 上典型表现是画面全黑）：

```python
# 子线程里
photo = ImageTk.PhotoImage(...)
self.display_label.config(image=photo)
```

Tkinter 不是线程安全的，`PhotoImage` 在非主线程创建会渲染成空图，严重时界面卡死。

**本项目写法**：

```python
# 子线程：只读帧，入容量 1 的队列；满了丢旧帧
while self.is_camera_open and self.cap:
    ret, frame = self.cap.read()
    self.current_frame = frame                    # 原图，拍照预测用
    small = cv2.resize(frame, (700, 400))
    try: self.frame_queue.put_nowait(small)
    except queue.Full:
        self.frame_queue.get_nowait(); self.frame_queue.put_nowait(small)

# 主线程：定时取帧刷新，约 33 FPS
def _refresh_display(self):
    frame = self.frame_queue.get_nowait()
    photo = ImageTk.PhotoImage(image=ui_common.frame_to_pil(frame))   # ★ 主线程创建
    self.display_label.config(image=photo); self.display_label.photo = photo
    self.root.after(30, self._refresh_display)    # ★ 不用 time.sleep，不阻塞事件循环
```

三个要点：控件操作全在主线程；队列 `maxsize=1` 保实时性；`root.after` 定时。

#### 5.5.3 BGR → RGB

```python

```

OpenCV 是 BGR，训练数据是 RGB，不转换会出现"蓝色玫瑰"这种离谱误判。

### 5.6 知识蒸馏：`6.distillation_cnn.py`

#### 5.6.1 原理

用教师的**输出概率分布**（软标签）指导学生训练。相比 0/1 硬标签，软标签携带"像玫瑰但更像菊花"这类类别间相似性信息。

#### 5.6.2 损失函数（已修正为标准形式）

```
Loss = α · T² · KL( softmax(student/T) ‖ softmax(teacher/T) ) + (1-α) · CE(student, label)
```

```python
student_soft = F.log_softmax(student_logits / T, dim=1)
teacher_soft = F.softmax(teacher_logits / T, dim=1)
soft_loss = KLDivLoss(reduction="batchmean")(student_soft, teacher_soft) * (T ** 2)
hard_loss = CrossEntropyLoss()(student_logits, labels)
total = alpha * soft_loss + (1 - alpha) * hard_loss
```

- **T**：温度，越大分布越平滑、暗知识越明显，经验 2~20，本项目 4；
- **乘 T²**：补偿除以 T 带来的 1/T 梯度因子，让软硬损失同量级；
- **α**：软损失权重，应取 0~1，本项目 0.7。

> 原水果文档的实现是 `α·soft + 1.0·hard` 且 `α=2.0`，这不是标准写法。改成本文公式后学生从 72.67% 到 73.33%，可作为课堂对比实验（α=2.0 vs 0.7）。

#### 5.6.3 教师冻结与训练

```python
teacher.eval()
for p in teacher.parameters(): p.requires_grad = False

with torch.no_grad(): teacher_logits = teacher(images)
student_logits = student(images)
loss, _, _ = loss_fn(student_logits, teacher_logits, labels)
optimizer.zero_grad(); loss.backward(); optimizer.step()
```

每轮在测试集评估，只在准确率提升时保存最优；`StepLR(5, 0.8)`。checkpoint 额外记录 `temperature`、`alpha`、`teacher_acc`、`best_test_acc`。

### 5.7 集成预测：`7.distillation_predictor.py`

#### 5.7.1 双模型加载与一致性校验

```python
if teacher_classes != student_classes:
    messagebox.showerror("错误", "类别顺序不一致，集成结果会完全错乱")
```

两个模型分别训练，若类别顺序不同，同一个下标 2 在教师里是"玫瑰"、学生里可能是"菊花"，集成必然错。因此启动就校验，不一致直接拒绝运行。

#### 5.7.2 集成方式：先平均 logits 再 softmax

```python
ensemble_logits = (teacher_logits + student_logits) / 2.0
prob = torch.softmax(ensemble_logits, dim=1)
```

不是"两个概率取平均"——前者保留 logits 的尺度信息，通常效果更好。

#### 5.7.3 后台评估准确率

按钮点了之后：`ttk.Progressbar` 走 indeterminate → 子线程跑测试集（教师/学生/集成各算一遍）→ 结果放 `queue` → 主线程 `root.after(100, ...)` 轮询并 `messagebox`。**绝不在子线程直接弹 messagebox。**

### 5.8 迁移学习：`8.train_resnet.py`

```python
net = torchvision.models.resnet18(weights=ResNet18_Weights.DEFAULT)
net.fc = nn.Linear(net.fc.in_features, num_classes)
```

- 只换最后一层，其余权重用 ImageNet 预训练初始化；
- 同样 128×128 输入、同样增强，Adam(lr=1e-3)，`StepLR(5, 0.5)`，15 轮；
- 保存时写 `"arch": "resnet18"`，`ui_common.load_model()` 靠这个字段选对结构。

## 7. 实验结果

### 7.1 准确率对比

| 模型 | 轮数 | 训练 acc | 测试 acc | 耗时（CPU） |
|---|---|---|---|---|
| 教师 PlantCNN | 40 | 77.8% | **72.67%**（第 30 轮） | 10.0 min |
| 学生（蒸馏 T=4, α=0.7） | 40 | — | **73.33%**（第 40 轮） | 11.4 min |
| ResNet18 迁移学习 | 15 | 98.8% | **90.67%**（第 15 轮） | 5.4 min |

### 7.2 逐类准确率（测试集每类 30 张）

| 类别 | PlantCNN | ResNet18 |
|---|---|---|
| 兰花 | 80.00% | **100.00%** |
| 向日葵 | 86.67% | 90.00% |
| 玫瑰 | 80.00% | 86.67% |
| 菊花 | 56.67% | 90.00% |
| 郁金香 | 60.00% | 86.67% |

### 7.3 为什么自建 CNN 只有 72%、蒸馏只涨 0.67 个百分点

1. **标签噪声**：网络采集的图里混进大量非目标样本。菊花类里有菊花茶、菊花展全景；郁金香类里常有整片花海远景（花只占几个像素）。这些样本无论怎么训都"学不对"，7.2 里这两类最低就是直接证据。
2. **测试集只有 150 张**：一张图 = 0.67 个百分点，准确率抖动很正常。
3. **模型容量**：4 层 CNN 2.34 M 参数，够分 5 类，但对复杂背景不鲁棒。
4. **蒸馏的前提是教师有"暗知识"可教**：教师本身 72.67% 且错误主要来自标签噪声，软标签传递的也是噪声，所以提升有限。想看到明显提升，应该先有一个强教师（例如 90% 的 ResNet），再蒸馏给轻量学生——这也是"压缩模型"的正确用法。

### 7.4 曲线怎么读

- 训练 acc 持续升、测试 acc 停滞或下降 → 过拟合（ResNet18 第 10 轮后就是这种状态，靠"只保存最优"兜住）；
- 训练 acc 和测试 acc 一起低 → 欠拟合（PlantCNN 前 20 轮，加轮数/加容量）；
- 正常收敛：两条曲线同步上升并逐渐靠近。

| 中文标题变方块 | 缺字体 | 已设 `Microsoft YaHei`，换机器改字体名 |

## 9. 项目扩展方向

1. **数据清洗自动化**：用当前模型给训练集打分，把"高置信度分错"的样本挑出来人工复核，两三轮就能把标签噪声压下去，往往比换模型更有效。
2. **更强 backbone**：ResNet50 / EfficientNet-B0 / ConvNeXt-Tiny，配合 160 或 224 输入。
3. **蒸馏的正确用法**：先用 ResNet18 当教师（90.67%），蒸馏给 PlantCNN 学生，再看学生能不能到 85%+；这才是"大模型教小模型"的压缩场景。
4. **拒识能力**：Softmax 最大概率低于阈值就输出"不是这 5 类"，避免把任意图片强行归类。
5. **部署**：导出 ONNX / NCNN；或 Flask 包成 HTTP 接口，网页上传图片返回类别。
6. **换课题**：花卉病虫害（细粒度 + 病斑定位）、花卉品种细粒度分类（同色同形，需注意力机制）、杂草识别（先检测后分类）。只需改 `plant_config.py` 的类别与关键词重跑。

### 11.5 三个关键实现

**模型只加载一次。** Flask 默认每个请求独立，若在视图里 `load_model()` 会反复读 45 MB 权重。用模块级字典做单例：

```python
_MODELS = {}

def get_main_model():
    if "main" not in _MODELS:          # 首次请求才加载
        _MODELS["main"] = ui_common.load_model()
    return _MODELS["main"]
```

**图片不落原图。** 原图可能 10 MB，历史记录只需要缩略图：用 `PIL.thumbnail((260,260))` 存成 JPEG 放 `web/static/uploads/`，页面直接 `/static/uploads/xxx.jpg` 引用，识别记录只存路径。

**没重训也能出准确率。** 管理端表格读的是 checkpoint 里的元数据（`best_accuracy`、`arch`、`class_names`、`epochs`），和训练脚本写进去的字段完全一致，所以三个模型的数字（90.67% / 72.67% / 73.33%）是训练时的真实结果，不是页面里手写的常量。

### 11.6 实测（本机自测脚本结果）

5 张演示图经 HTTP 上传后的返回：兰花 98.83%、向日葵 100%、玫瑰 100%、菊花 53.48%、郁金香 99.17%，单张 17~25 ms；用户历史 5 条；普通用户访问 `/admin` 返回 302；管理员页面模型表、数据集表、日志表均正常渲染；错误密码返回提示。

### 11.7 与桌面端的关系

两者共用 `plant_config.py`、`model.py`、`ui_common.py`，改类别、换模型只改一处，三个入口（本地图片 / 摄像头 / 网页）同时生效。论文/答辩里可以表述为"同一推理内核、三种交付形态（桌面 GUI、实时摄像头、B/S 网页）"。

### 11.8 可继续做

- 管理端加"模型热切换"（下拉选择后重载 `_MODELS`）；
- 加低置信度拒识（`confidence < 60` 判为"疑似非这 5 类"并记录）；
- 用 `gunicorn`/`waitress` 替换开发服务器，`host` 改 `0.0.0.0` 后局域网内其他机器可访问，配上登录限流更稳。
